# astack decision log

Append-only. Each entry records what was chosen, what was rejected, and what would
reopen it.

## D001 — astack is a thin plugin, not a transformed gstack fork
Date: 2026-09-13
Status: active

**Decision.** Empty the `garrytan/gstack` fork and build astack as a small native
Claude Code plugin. Keep the fork's history on the `gstack-upstream-v1.84.1` branch
and on both remotes.

**Evidence.** The fork was pristine — 391 commits, none by Amol, zero commits behind
`upstream/main`. It is 1,601 files, 963 of them TypeScript, including a Playwright
browser CLI, a PDF renderer and a Chrome extension. It could not run on this machine:
Bun was not installed, and upstream's own README documents Windows as a degraded
target requiring `./setup` to be re-run after every `git pull`.

**Rejected.**
- *Overlay on the fork* — keeps the browser, PDF and eval machinery, but costs a Bun
  install, the Windows degraded path, skill-name collisions with ECC, and a weekly
  upstream merge forever. The browser tooling it buys is already available through
  `claude-in-chrome`, which the logs show being used more.
- *Full transform* — severs upstream permanently and means owning 963 TypeScript
  files of someone else's product.

**Reopen when.** A workflow genuinely needs gstack's eval harness or its headless
browser, and `claude-in-chrome` cannot do the job.

## D002 — astack calls superpowers rather than absorbing it
Date: 2026-09-13
Status: active

**Decision.** `superpowers:brainstorming` and `superpowers:writing-plans` stay
installed. astack references them by name and does not reimplement them.

**Evidence.** They are the second and fourth most-invoked skills in the workspace.
Their content is better than a fresh rewrite: brainstorming's Spike / Bounded /
Architectural classifier is already the adaptive workflow-depth mechanism astack
would otherwise have to build, and it carries a hard approval gate.

**Rejected.** Copying them into astack for the sake of a single namespace. That
trades real quality for tidiness and forks a maintained project.

**Reopen when.** `astack:audit` shows they are being invoked through astack often
enough that owning them beats depending on them, or superpowers stops being
maintained.

## D003 — no code-graph tool yet
Date: 2026-09-13
Status: active

**Decision.** Do not install `codegraph`, `codebase-memory-mcp`, or `Graft` now.

**Evidence.** All three solve code-structure memory and benchmark on large repos —
`codebase-memory-mcp` on the 28M-LOC Linux kernel. The largest Easeur repo is
`workout` at 141 source files and 57K LOC. 32% of logged bash commands are
exploration-shaped, but at that repo size most of it is re-reading known files, which
a graph does not fix. Two of the three also add context cost (15 MCP tools, a shared
daemon) while astack exists to cut it.

**Rejected.** `codebase-memory-mcp` despite being the most engineered of the three:
15 tools, a daemon, 287 MB and agent-config rewriting are the shape of thing being
removed. Its README headline claims 120x fewer tokens; its own arXiv paper reports
10x across 31 repos.

**Reopen when.** A repo passes roughly 500 source files, or `astack:audit` shows
exploration still dominating token spend. First choice at that point is `codegraph` —
one MCP tool by design, no daemon. Watch `Graft`: it is the only one graded by an
external harness (SWE-bench Verified, 54% to 66% correctness).

## D004 — diagram-first output is a spine rule, not a preference
Date: 2026-09-13
Status: active

**Decision.** Any answer with structure leads with an ASCII diagram, then at most
three bullets. Written into the spine so it applies to every skill.

**Evidence.** Amol stated it directly, after re-invoking `/caveman` mid-session
following a long prose answer. Long prose gets skimmed, so the substance does not land.

**Reopen when.** Never, without him saying so.

## D005 — ECC is disabled and indexed, not uninstalled
Date: 2026-09-14
Status: active

**Decision.** ECC stays on disk at `~/.claude/plugins/marketplaces/ecc` with
`"ecc@ecc": false` in settings. `docs/reference/ecc-catalogue.md` indexes all 68 agents
and 285 skills with their descriptions, regenerated by
`scripts/gen-ecc-catalogue.cjs`.

**Evidence.** A disabled plugin costs zero session tokens, so there is no reason to
delete it. Amol asked to keep the knowledge available: "so that i would have known ecc
had these plugins, later i will include it here."

**Rejected.** Uninstalling. That would recover no tokens and lose a catalogue worth
having when a future need appears.

**Consequence.** ECC's `chrome-devtools` MCP server disappears with the plugin, so it
is preserved separately in astack's own `.mcp.json` — 283 tool calls in two months make
it the one genuinely load-bearing thing ECC provided.

**Reopen when.** ECC ships something worth enabling wholesale, or the catalogue goes
long enough without being consulted that the install is dead weight on disk.

## D006 — a deterministic router, not better skill descriptions
Date: 2026-09-14
Status: active

**Decision.** A `UserPromptSubmit` hook classifies each prompt and injects a single
line naming the one skill that fits.

**Evidence.** Amol: "its quite possible i would forget to invoke a skill manually."
The data agrees — 55 skill invocations across 250 sessions, against 350 available
skills. Relying on the model noticing a matching description is what produced that
number.

Three constraints make it work rather than become noise: one recommendation and never a
menu, silence below a score threshold, and never firing when a skill was already named.
20 cases are pinned in the test suite, because a router whose accuracy is not tested is
a router that silently drifts.

**Rejected.**
- *Better skill descriptions alone* — that is the mechanism that already failed at
  scale.
- *A classifier skill* — it would have to be invoked, which is the original problem.
- *Recommending several skills* — a menu is what astack exists to escape.

**Reopen when.** `/audit` shows the router firing on trivia, or missing prompts often
enough to be noise in the other direction.

## D007 — product context carries verified facts, not repeated notes
Date: 2026-09-14
Status: active

**Decision.** Every concrete claim in `context/products/*.md` is checked against the
repo before being written, and `/audit` re-checks them.

**Evidence.** Three claims verified exactly on 2026-09-14: `workout/out` holds 10,279
files; `workout/wrangler.jsonc` has no `main`; the landing page's `deploy.yml` has
`workflow_dispatch` as its only trigger. One real gap found in the process — the Wear
prototype lives at `wear/UI-areana-ai/`, so a plain scan of `wear/` finds nothing and
concludes the repo is empty.

This is the same failure the workspace already paid for once: `workout/BUILD_STATE.md`
carried "no successful signup verified yet" for seven days while two rows sat in the
table, because every status pass re-read the note instead of querying the table.

**Reopen when.** Never. A context file that repeats an unverified claim is worse than
an empty one, because it is trusted.

## D008 — design is one astack skill; impeccable called, not vendored
Date: 2026-10-02
Status: active

**Decision.** `skills/design` absorbs the transferable rules from three reviewed repos
as markdown: the brief read, the three dials and the system map idea from taste-skill
(MIT), the register split and critique/audit/system moves from impeccable (Apache-2.0),
and the resilience rules from ui-ux-pro-max (MIT). Impeccable itself is optional and
installed deliberately. None of the three is copied wholesale.

**Evidence.** Reviewed 2026-10-02 against the repos. taste-skill is one 87 KB file that
declares itself out of scope for dashboards and product UI. ui-ux-pro-max maps product
type to a fixed palette and fonts, which is the template effect the others fight, and
its provenance records are self-assigned. impeccable has the evaluation moves astack
lacked (critique, audit, extract) but downloads an engine binary on first run, ships
pre-1.0 releases daily, and can install edit hooks.

**Rejected.**
- *Install all three* — four skills (with frontend-design) giving conflicting orders on
  the same request, and 87 KB of context on every taste-skill trigger.
- *Vendor impeccable's files* — its engine is a binary and a 4 MB browser bundle;
  copying it makes astack own an upgrade path it cannot test.
- *ui-ux-pro-max design-system generator* — product-type lookups produce generic output.

**Reopen when.** `/audit` shows `design` unused for a month, or impeccable reaches 1.0
and a trial on `workout/` shows its detector catching defects `web` VISUAL mode missed.
